# Конспекты уроков хореографии

Android-приложение для педагога-хореографа: конспекты уроков с видео и музыкой,
календарь занятий и таймер для проведения урока. Один пользователь, всё хранится
локально на планшете, установка APK-файлом.

Полное техзадание — [ТЗ.md](./ТЗ.md), ход работ — [PROGRESS.md](./PROGRESS.md).

## Стек

- Expo SDK 57, React Native 0.86, TypeScript, `expo-router` (файловая маршрутизация)
- `expo-sqlite` + Drizzle ORM с миграциями, доступ к данным только через `src/db/repositories/*`
- `expo-file-system` — материалы копируются в приватную папку приложения
- `zustand` — состояние интерфейса, `dayjs` с русской локалью — даты
- Только Android, `minSdkVersion` 24, обе ориентации экрана

## Разработка

```bash
npm install                 # зависимости
npx expo start              # dev-сервер (Expo Go не подойдёт: нужны нативные модули)
npm run typecheck           # tsc --noEmit
npm run lint                # ESLint
npm test                    # Jest: репозитории и расчёт времени урока
npm run db:generate         # новая миграция после правки src/db/schema.ts
```

Тестовые данные (2 группы, 3 конспекта, 5 материалов) создаются автоматически
при первом запуске **dev**-сборки. В release-сборке база пустая.

### Структура

```
app/            маршруты expo-router (только навигация)
src/db/         схема, миграции, репозитории, сид
src/features/   экраны по доменам
src/ui/         базовые компоненты интерфейса
src/theme/      токены, светлая и тёмная тема
src/lib/        файлы, даты, расчёт времени
plugins/        config-плагины Expo (подпись release-сборки)
```

## Сборка APK

Оба пути дают один и тот же APK. Локальный не требует интернета и лимитов,
EAS не требует Android SDK на компьютере.

### Шаг 0. Ключ подписи (делается один раз)

APK подписывается ключом. **Ключ нельзя терять.** Новая версия приложения
устанавливается поверх старой только если подписана тем же ключом. Если ключ
потерян, придётся удалить приложение и поставить заново — а вместе с ним
**удалятся все конспекты, материалы и настройки**, потому что данные лежат в
приватной папке приложения.

```bash
keytool -genkeypair -v \
  -keystore choreonotes.keystore \
  -alias choreonotes \
  -keyalg RSA -keysize 2048 -validity 10000
```

`keytool` идёт вместе с JDK. Команда спросит пароль (запомнить!) и данные владельца.

Полученный `choreonotes.keystore` положить в `android/` и рядом создать
`android/keystore.properties`:

```properties
storeFile=choreonotes.keystore
storePassword=пароль_хранилища
keyAlias=choreonotes
keyPassword=пароль_ключа
```

Оба файла в `.gitignore` — в репозиторий они не попадают.

> **Копию keystore и пароль хранить там же, где резервные копии данных**
> (раздел «Резервная копия» в настройках приложения). Потеря ключа = потеря
> возможности обновлять приложение без стирания конспектов.

### Путь 1. Локальная сборка

Нужны JDK 17+ и Android SDK (Android Studio или `sdkmanager`), переменная
`ANDROID_HOME` должна указывать на SDK.

```bash
npx expo prebuild --platform android   # генерирует папку android/ из app.json
cd android
./gradlew assembleRelease
```

Готовый файл: `android/app/build/outputs/apk/release/app-release.apk`

Важно: `npx expo prebuild` пересоздаёт папку `android/`, поэтому руками её не
правят — все настройки живут в `app.json` и в `plugins/`. Файлы
`android/choreonotes.keystore` и `android/keystore.properties` prebuild не трогает,
но перед `--clean` их стоит скопировать в надёжное место.

Если `android/keystore.properties` отсутствует, сборка подпишется отладочным
ключом: поставить такой APK можно, но обновить его потом не получится.

### Путь 2. EAS Build

Android SDK не нужен, сборка идёт в облаке Expo, на выходе — ссылка, по которой
APK скачивается прямо на планшет.

```bash
npm install -g eas-cli
eas login
eas build:configure          # один раз
eas build --platform android --profile preview
```

Профиль `preview` в `eas.json` уже настроен на `"buildType": "apk"` и
`"distribution": "internal"`. При первой сборке EAS предложит сгенерировать
keystore — можно согласиться (тогда ключ хранится в аккаунте Expo,
`eas credentials` позволяет его скачать) или загрузить свой из шага 0.

### Версионирование

Перед каждой новой сборкой, которая ставится поверх предыдущей, увеличить
`versionCode` в `app.json` (`expo.android.versionCode`): 1 → 2 → 3 …
Android не даст установить APK с тем же или меньшим `versionCode`.
`version` («1.0.0») — то, что видит человек, его меняют по желанию.

### Резервные копии

Данные (база и все видео) лежат в приватной папке приложения. Их **не видно**
в файловом менеджере, они **не попадают** в облачные бэкапы Google и
**удаляются вместе с приложением**. Единственный способ их сохранить —
«Настройки» → «Создать копию».

Что происходит при экспорте:

1. база и папки `materials/`, `thumbnails/` складываются во временную папку;
2. всё это пакуется в один файл `choreonotes-backup-ГГГГ-ММ-ДД.zip`;
3. открывается системный диалог «Поделиться» — оттуда архив сохраняют
   в «Загрузки», на карту памяти или отправляют в облако.

Восстановление: «Настройки» → «Восстановить из копии» → выбрать .zip.
Приложение проверит, что архив свой, и **заменит все текущие данные**
содержимым архива. После восстановления приложение лучше закрыть и открыть
заново.

Если последней копии больше 14 дней, на календаре появляется плашка-напоминание.

> Копию `.zip` и файл keystore имеет смысл хранить рядом: без keystore не
> обновить приложение, без копии не вернуть конспекты.

### Установка на планшет

1. Скопировать APK на планшет (кабель, облако, ссылка EAS).
2. Открыть файл через «Проводник» или «Загрузки».
3. Android спросит про установку из неизвестных источников — «Настройки» →
   разрешить для приложения, из которого открывается файл (обычно «Файлы» или
   браузер). На Android 8+ разрешение выдаётся отдельно каждому приложению:
   «Настройки» → «Приложения» → «Специальный доступ» → «Установка неизвестных
   приложений».
4. Установить и открыть.

Обновление ставится поверх старого APK и сохраняет все данные — при условии
того же ключа подписи и большего `versionCode`.

### Порядок при первой установке

1. Сгенерировать keystore (шаг 0) и сохранить его копию отдельно от планшета.
2. Собрать APK любым из двух путей.
3. Разрешить установку из неизвестных источников и поставить APK.
4. Открыть приложение, создать группу и первый конспект.
5. Сразу сделать пробную резервную копию и проверить, что .zip сохранился
   туда, откуда его можно достать (например, в «Загрузки»).

### Проверка перед тем, как доверить приложению рабочие конспекты

Полный сценарий из раздела 9 ТЗ, который стоит пройти руками один раз:
создать группу и шаблон, создать урок, добавить в него видео с планшета,
убедиться, что видео появилось в общей базе, выбрать то же видео в другом
блоке с таймкодом, проверить счётчик времени, провести урок с таймером
и поворотом планшета, сделать бэкап в «Загрузки», удалить приложение,
поставить APK заново и восстановиться из архива.
